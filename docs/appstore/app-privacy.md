# App Privacy・年齢区分・輸出コンプライアンス（App Store Connect 回答案）

## 1. App Privacy（アプリのプライバシー）

### 回答

| 質問 | 回答 |
|---|---|
| このアプリまたはサードパーティパートナーは、このアプリからデータを収集しますか？ | **いいえ、データを収集していません (Data Not Collected)** |

→ すべてのデータタイプが「収集しない」となり、アプリページには「データの収集なし」と表示される。トラッキング用の質問（ATT）は出ない。ATT（App Tracking Transparency）の許可ダイアログも不要。

### 根拠（Apple の定義: 「収集」＝ 端末外に送信し、リクエスト処理に必要な期間を超えて保持すること）

| データ種別 | 扱い | 収集に該当しない理由 |
|---|---|---|
| 現在地（精確な位置情報） | 距離計算・地図表示にのみ使用 | **端末内でのみ処理**。運営サーバー・第三者へ送信せず、保存・キャッシュもしない（距離もキャッシュしない。今回のアプリ修正で対応） |
| 検索文字列（住所・駅名） | 地域選択時に Apple の地図／ジオコーディングへ送信 | Apple の OS 標準フレームワーク（MapKit / CLGeocoder 等）の機能。運営は受け取らず、保持しない |
| お気に入り | UserDefaults（端末内） | 端末外へ送信しない |
| 識別子・利用状況・診断 | 取得しない | 解析 / 広告 / クラッシュ収集 SDK なし。アカウントなし |
| 誤り報告フォーム | Google フォーム（ブラウザで開く外部サイト） | アプリ内で入力・送信を扱わない。店名・店舗IDを URL に載せて開くだけ。メールアドレスは収集しない設定 |
| カフェデータ取得（GitHub Pages） | 静的 JSON の GET | 利用者の情報を含まない。運営は GitHub のアクセスログを見ない |
| Instagram 埋め込み | WKWebView で instagram.com の埋め込みスクリプトを読み込み | 下記「リスク」参照 |
| リンクプレビュー（OGP） | 端末が直接リンク先を取得（LinkPresentation） | 運営は受け取らない。ユーザーがリンクを開くのと同種の直接アクセス |
| 「地図で写真を見る」 | 利用者のタップ時のみ、店名＋住所を検索語に Google マップの検索ページを SafariView で開く | 利用者自身の操作による外部サイト表示。運営は受け取らない。現在地は渡さない |
| 経路案内 | 目的地（店舗）座標を Apple マップ／Google マップに渡す | 利用者自身が選んだ外部アプリの起動。現在地は渡さない（出発地は各マップアプリが扱う） |

- プライバシーポリシー URL: https://changch223.github.io/puppy-with-cafe/docs/privacy.html（通信先を網羅して記載済み）
- `PrivacyInfo.xcprivacy`: Tracking = false / TrackingDomains = 空 / `NSPrivacyCollectedDataTypes` は空配列（収集なし）、Required Reason API は UserDefaults（CA92.1）のみ宣言。

### リスク・判断が必要な点（要確認）

1. **解消済み**: `PrivacyInfo.xcprivacy` の `NSPrivacyCollectedDataTypes` は、アプリ側の修正で空配列になった（2026-10-17 のワーキングツリー）。App Store Connect の「データを収集しない」と整合する。コミットされていることを提出前に確認する。
2. **Instagram 埋め込み**: WebView が instagram.com のスクリプトを読み込むため、Meta 側が IP アドレス等を受け取る。審査上は「Web ページを表示しているだけ（SDK は含まない）」として「収集なし」と回答できる見込みだが、保守的に回答するなら下記 B 案。**現方針は A 案**。
   - **A 案（現方針）**: データを収集していません。ポリシーに Instagram / Apple / Google への通信を明記して透明性を担保。
   - **B 案（保守）**: 「製品の操作に関するデータ → 使用状況データ」等を「収集する・ユーザーにリンクしない・トラッキングに使わない・目的: アプリの機能」で申告。審査リジェクトのリスクは下がるが、アプリページに「データの収集」が出る。
   - 審査でプライバシー関連の指摘が来たら B 案へ切り替える（回答は後から変更可能。ただしバイナリの再提出は不要）。
3. Apple マップ（MapKit）・Apple の LinkPresentation・位置情報は Apple 自身のサービスであり、開発者による「収集」には当たらない扱い。

## 2. 年齢区分（Age Rating）質問票の回答案

2025 年以降の新しい質問票（4+/9+/13+/16+/18+）の想定回答。**画面の実際の質問文に合わせて読み替える。**

| 質問 | 回答 |
|---|---|
| 暴力的なコンテンツ（漫画・リアル・極端な暴力など） | なし |
| 性的なコンテンツ・ヌード | なし |
| 不適切な言葉・下品なユーモア | なし |
| ホラー・恐怖をテーマにしたコンテンツ | なし |
| アルコール・タバコ・薬物の使用または言及 | なし（アプリはこれらを扱う機能・描写を持たない。カフェ情報の営業時間・メニュー欄に酒類を訴求する文言を載せていないかだけ最終確認） |
| 医療・健康に関する情報 | なし |
| ギャンブル（疑似含む）・コンテスト | なし |
| 無制限のウェブアクセス | **なし**（リンクは店舗サイト・SNS等の特定リンクを SafariView で開く。汎用ブラウザではない）。※ 質問が「アプリ内でウェブを自由に閲覧できるか」の場合も、任意の URL を入力する機能は無いので「いいえ」 |
| ユーザー生成コンテンツ | なし（Instagram 公式埋め込みの表示はあるが、アプリ内への投稿・共有機能は無い） |
| メッセージ／チャット | なし |
| 広告 | なし |
| アプリ内課金・ペアレンタルコントロール・年齢確認 | なし |

**想定結果: 4+**

## 3. 輸出コンプライアンス（Export Compliance）

- アプリは OS 標準の HTTPS（URLSession / WKWebView / MapKit）のみ使用。独自の暗号アルゴリズム・暗号ライブラリは使わない。
- `INFOPLIST_KEY_ITSAppUsesNonExemptEncryption = NO` を `project.pbxproj`（Debug / Release）に設定済み（2026-10-17 のワーキングツリーで確認。生成される Info.plist に `ITSAppUsesNonExemptEncryption = NO` が入る）。Archive 後の Info.plist でも最終確認する。
- 設定済みなら、ビルドアップロード時の「暗号化に関する質問」は表示されない。表示された場合: 「上記のいずれのアルゴリズムにも該当しない」を選択（標準暗号のみ＝免除）。
- フランスなど特定地域での配信に関する追加書類は、免除の場合は不要。

## 4. その他 App Store Connect で聞かれる項目

| 項目 | 回答案 |
|---|---|
| コンテンツ配信権 (Content Rights) | 「サードパーティコンテンツを含む」→ 権利を持つ／許諾を受けている に該当するか確認。店名・住所・営業時間等の事実情報は運営が公開情報から整備、写真は転載せず Instagram 公式埋め込み・OGP の直接取得のみ。座標はデジタル庁 ABR（公共データ利用規約）加工物。 |
| 広告 ID (IDFA) | 使用しない |
| 価格 | 無料 |
| 配信地域 | 日本（東京のみ対象のため）。他国での配信可否は任意 |
| 年齢制限・Made for Kids | 該当なし |
| DSA（EU トレーダー）ステータス | EU 配信しないなら対応不要。EU を含める場合は事業者情報の申告が必要（個人開発者は住所・電話の公開に注意） |
