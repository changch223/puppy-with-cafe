# Google フォーム（誤り報告＋お問い合わせ兼用）作成手順（後日導入する手順）

> **v1.0 はフォームなしで提出する**（窓口は GitHub Issues。報告ボタンは URL 未設定の間は自動で非表示）。本書は将来フォームを導入するときの手順として残す。導入時は §5 の `{{FORM_URL}}` 差し替えの代わりに、docs の GitHub Issues 記載をフォーム URL へ更新すること。

目的: アプリの「情報の誤りを報告」ボタンと、support.html / privacy.html の「お問い合わせ」で使うフォームを 1 つ作る。
方針: **メールアドレス・氏名などの連絡先は集めない**（プライバシーポリシーで「収集しない」と明記済み）。

## 0. アプリ側のプリフィル仕様（コードから確定した事実）

| 項目 | 内容 |
|---|---|
| 設定先 | `DokoWanCafe/DokoWanCafe/App/AppConfig.swift` の `AppEnvironment.defaultReportFormTemplate`（`String?`。現在 `nil`）。※ ファイル名は AppConfig.swift だが型名は `AppEnvironment` |
| 未設定（nil / 空）のとき | 店詳細の「情報の誤りを報告」ボタン自体が表示されない（`AppEnvironment.isReportFormConfigured()`）→ v1.0 はこの状態（フォームなし）で提出する。導入する版では審査メモも更新する |
| プレースホルダ | `{cafe_name}`（店名。アプリが URL エンコード済みで置換。`& = +` もエンコードされる）と `{cafe_id}`（店舗 UUID。小文字・ハイフン付き） |
| 置換の実装 | `AppEnvironment.reportFormURL(cafeName:cafeID:)`。テンプレート文字列に対する単純な文字列置換 → `URL(string:)` |
| 開発時の上書き | 環境変数 `REPORT_FORM_URL`（Xcode の Scheme > Run > Environment Variables）。コードを触らずに動作確認できる |
| 必要な entry | **店名**用 1 つ（`{cafe_name}`）＋ **店舗ID**用 1 つ（`{cafe_id}`）。「種類」の既定値（情報の誤り報告）も entry として固定値で入れる（任意だが推奨） |
| 注意 | テンプレートに日本語などの非 ASCII の固定値を入れる場合は **パーセントエンコード済み**で書くこと（iOS 16 の `URL(string:)` は非 ASCII を含む文字列で nil を返し、`reportFormURL` が nil になり、店詳細の「情報の誤りを報告」ボタンが表示されなくなる。現在のアプリは iOS のバージョンに関わらず、テンプレートに生の非 ASCII があれば未設定扱いにする） |

テンプレートの形（`<FORM_ID>` と `entry.<数字>` は後述の手順で取得）:

```
https://docs.google.com/forms/d/e/<FORM_ID>/viewform?usp=pp_url&entry.<種類のID>=%E6%83%85%E5%A0%B1%E3%81%AE%E8%AA%A4%E3%82%8A%E5%A0%B1%E5%91%8A&entry.<店名のID>={cafe_name}&entry.<店舗IDのID>={cafe_id}
```

- `%E6%83%85%E5%A0%B1%E3%81%AE%E8%AA%A4%E3%82%8A%E5%A0%B1%E5%91%8A` ＝「情報の誤り報告」（選択肢の文言と**完全一致**させる。変えたらエンコードし直す）
- `{cafe_name}` `{cafe_id}` は **そのまま波括弧つきで書く**（アプリが置換する）
- ※ 「種類」の既定値を入れない場合は `&entry.<種類のID>=...` の部分を省く（アプリからの報告でもフォーム上で選ばせる）

## 1. フォームを作る（forms.google.com）

1. 新しいフォームを作成。タイトル: **Puppy With Cafe 情報の誤り報告・お問い合わせ**
2. 説明文（先頭）:
   > 掲載情報の誤り報告・お問い合わせ用フォームです。いただいた内容は運営が確認し、正しいと判断したものだけが反映されます（即時には反映されません）。**氏名・電話番号・メールアドレスなどの個人情報は書かないでください。**このフォームでは連絡先を集めていないため、個別のご返信はできない場合があります。
3. 設問（この順で）:

| # | 設問 | 形式 | 必須 | 補足 |
|---|---|---|---|---|
| 1 | 種類 | ラジオボタン | 必須 | 選択肢: 「情報の誤り報告」「お問い合わせ・ご要望」（文言は上のエンコード値と一致させる） |
| 2 | 店名 | 記述式（短文） | 任意 | 説明: 「アプリから開いた場合は自動で入力されます」 |
| 3 | 店舗ID | 記述式（短文） | 任意 | 説明: 「アプリから開いた場合は自動で入力されます。変更しないでください」 |
| 4 | 誤っている項目（誤り報告の場合） | チェックボックス | 任意 | 犬の同伴可否・条件 / 営業時間・定休日 / 閉店・移転 / 住所・場所（地図の位置） / 電話・リンク（公式サイト等） / その他 |
| 5 | 内容 | 記述式（長文） | 必須 | 説明: 「どこがどう違うか、または質問・ご要望の内容を具体的に」 |
| 6 | 根拠（任意） | 記述式（長文） | 任意 | 説明: 「公式サイトの URL、確認した日付など。個人情報は書かないでください」 |

- 連絡先（メール・電話・SNS アカウント）の設問は**作らない**。

## 2. 設定（歯車アイコン／「設定」タブ）— 個人情報を集めないための必須設定

1. **回答 > メールアドレスを収集する: OFF**（「収集しない」。「確認済み」「回答者からの入力」も選ばない）
2. **回答 > 回答のコピーを回答者に送信: OFF**
3. **回答を 1 回に制限する: OFF**（ONにすると Google ログインが必須になり、ログイン不要の方針に反する）
4. **回答の編集を許可: OFF**
5. **ファイルのアップロード設問は作らない**（ログインが必要になる）
6. 「回答」タブ > スプレッドシートにリンク → 回答先を、既存のマスター Sheet の新しいタブ、または**専用の新規 Sheet** に設定（`tools/README.md` 初回セットアップ 手順1・2 参照）。メール通知を使う場合は「新しい回答についてのメール通知を受け取る」を ON（通知は運営のみ）
7. 「送信」> リンク > **短縮 URL ではなく** `https://docs.google.com/forms/d/e/<FORM_ID>/viewform` 形式の URL を控える（`<FORM_ID>` は `1FAIpQLS...` で始まる長い文字列）
8. フォームを**公開（リンクを知っている全員が回答可）**にしてあることを、**ログアウトした状態／別端末のブラウザ**で開いて確認する

## 3. プリフィル URL と entry ID の取得

1. フォーム編集画面の右上「︙」メニュー > **事前入力したURLを取得**
2. 開いたプレビュー画面で、次のダミー値を入れる:
   - 種類: 「情報の誤り報告」を選択
   - 店名: `CAFENAME`
   - 店舗ID: `CAFEID`
3. 下部の「リンクをコピー」を押す。コピーされた URL は次のような形:
   ```
   https://docs.google.com/forms/d/e/<FORM_ID>/viewform?usp=pp_url&entry.111111111=%E6%83%85%E5%A0%B1...&entry.222222222=CAFENAME&entry.333333333=CAFEID
   ```
4. `CAFENAME` が付いている `entry.<数字>` が店名用、`CAFEID` が付いているものが店舗ID用、日本語（エンコード済み）が付いているものが種類用。
5. 値の部分を置き換えて**テンプレートを完成**させる: `CAFENAME` → `{cafe_name}`、`CAFEID` → `{cafe_id}`（種類の値はコピーされたエンコード済みの文字列のまま残す）

## 4. アプリへの反映

1. `DokoWanCafe/DokoWanCafe/App/AppConfig.swift` の
   ```swift
   static let defaultReportFormTemplate: String? = nil
   ```
   を、完成したテンプレート文字列に差し替える（コミット対象。フォームの URL は公開情報で機密ではない）。
2. 動作確認: ビルドして店の詳細 > 「情報の誤りを報告」> 「報告フォームを開く」で、**店名・店舗ID・種類が自動入力されている**ことを確認。店名に `&` や `・` を含む店でも崩れないこと。
3. 実機 / シミュレータで確認するだけなら、環境変数 `REPORT_FORM_URL` にテンプレートを入れて試すこともできる（コード変更なし）。
4. `tools/README.md` の記述・プロジェクト `CLAUDE.md` の「設定予定（未作成）」を「設定済み」に直す。

## 5. docs の問い合わせ窓口をフォームへ切り替える（導入時）

v1.0 時点（2026-10-18）の `docs/privacy.html` / `docs/support.html` には、問い合わせ窓口として **GitHub Issues** を記載してあり、`{{FORM_URL}}` のようなプレースホルダは残っていない。フォームを導入するときは、置換ではなく**本文から書き直す**。

`<FORM_URL>` ＝ **プリフィルなしのフォーム URL**（`https://docs.google.com/forms/d/e/<FORM_ID>/viewform`）。

| ファイル | 書き直す箇所 |
|---|---|
| `docs/privacy.html` | 「4. 誤り報告・お問い合わせ（GitHub Issues）」の節を、フォーム前提の本文に書き直す（Google フォームに接続される旨・店名と店舗IDが自動入力される旨・個人情報を書かないこと・連絡先を求めないこと）。GitHub Issues に関する記述（「現在の版にはボタンやフォームは含まれていません」を含む）は削除または併記に改める |
| `docs/privacy.html` | 「1. 収集しない情報」「5. 第三者提供・トラッキング」の「本アプリを通じては」という限定表現と、「8. 改定・お問い合わせ」の連絡先リンク |
| `docs/support.html` | 「Q. 情報の誤りを見つけました」と「お問い合わせ」を、アプリ内の報告ボタン（詳細画面の「情報の誤りを報告」）とフォームの案内に書き直す |

書き直したら、確認用に次を実行する（手順書自体は対象外にするため `docs/*.html` に限定する）:

```bash
grep -n "FORM_URL\|github.com/changch223/puppy-with-cafe/issues" docs/*.html   # 意図した箇所だけが残る（フォーム導入後は Issues の記載が残っていないこと）
```

差し替え後 `main` へマージ → GitHub Pages に反映されたら、`support.html` のフォームリンクから実際にフォームが開くか確認する。
