# 日本の類似アプリ UI/UX ベンチマーク

- 調査日: 2026-08-05
- 対象: 犬同伴OKカフェ発見アプリ「Puppy With Cafe」の改善に向け、日本市場で参照価値の高いグルメ発見系5本・ペット特化系5本を横断調査した結果の統合。

---

## 1. 調査対象一覧

グルメ発見系（成熟した地図・一覧・信頼性設計の参照元）:

- [食べログ](apps/tabelog.md) — 国内最大級のグルメDB。地図⇄一覧シームレス切替と「点数」中心の設計。非公開アルゴリズムの信頼性論争が反面教師。
- [Retty](apps/retty.md) — 実名口コミ型。シーン軸フィルタ（おひとりさま/子連れ/デート）とTOP USER制度で「誰が推すか」を信頼の核に。
- [ホットペッパーグルメ](apps/hotpepper-gourmet.md) — 予約特化。地図上のグレー円＋空マークで「今すぐ入れるか」を視覚化。2026年に口コミを肯定のみ→包括表示へ転換。
- [Googleマップ](apps/google-maps.md) — 汎用地図。Compact/Fullの2段階情報開示をAPIレベルで体系化。pet-friendlyフィルタは非搭載で要望が続く空白。
- [サウナイキタイ](apps/sauna-ikitai.md) — ニッチ趣味特化。100項目超の細分化フィルタと「客観データ最優先→UGC後段」の詳細設計。

ペット・犬特化系（直接の競合・隣接サービス）:

- [おでかけわんこ部](apps/odekake-wanko-bu.md) — 月50〜70万人メディア母体。MAP検索主導線、店内OK/大型犬可/テラス席のシーン絞込。2026年1月アプリ化。
- [Wan!Pass（ワンパス）](apps/wanpass.md) — 30万人超・6,000施設。犬プロフィール（犬種/体格）連動フィルタ＋証明書審査＋QRチェックインが軸。
- [itsumo dog（旧ドッグカフェ.jp）](apps/itsumo-dog.md) — Web型ポータル。こだわり条件数十項目、犬同伴バッジと利用マナー11項目を分離提示。地図は詳細内1タブ。
- [BringFido](apps/bringfido.md) — 米国のペット旅行OTA。全施設への電話一次確認＋ペット保証。骨マーク評価などプレイフルなブランド言語。
- [ドッグパークJP](apps/dog-park-jp.md) — 国内新興。地図/一覧2ボタン切替＋2色凡例。スマートロック解錠・リアルタイム入場定員が特徴（ローンチ初期）。

## 3. 日本市場のベストプラクティス10箇条

1. **地図はピン→簡易カード→詳細の2段階開示（progressive disclosure）を基本にする。** 地図タップ直後は要点のみ、詳細画面でフル情報という段階開示が業界標準。GoogleマップはCompact/FullとしてAPIレベルで明文化しており、食べログ・Retty・BringFidoも「ピン→簡易カード→詳細」の同型を採る。

2. **「探す→行動」の距離を最短化する。** 詳細に深く入らずとも一覧・地図・簡易カードの段階で主要CTA（経路・電話・予約）へ届く導線が評価される。食べログは地図ページに予約ボタンを追加し、ホットペッパーは地図から即「席押さえ」できる。

3. **主要CTAは画面下部に固定・強調する。** グルメアプリ共通のパターンとしてフッター固定の「電話をする」/「予約」ボタンが挙げられ、CTAの主軸はサービスごとに異なる（食べログ＝予約、Retty＝電話）が、いずれも下部固定で常時到達可能にしている。

4. **可否だけでなく「条件・設備」を第一級のフィルタ軸にする。** おでかけわんこ部（店内OK/大型犬可/テラス席あり）、itsumo dog（中型/大型犬OK/店内OK）、Wan!Pass（犬種・体格連動）、サウナイキタイ（細分化フィルタ）が示す通り、飼い主が本当に知りたい具体条件で絞り込めることが専用アプリの価値になる。

5. **詳細は「意思決定に直結する客観データを最上部、UGC・周辺情報は後段」の順で並べる。** サウナイキタイの詳細は温度（数値）→設備→アメニティ→サ活（口コミ）→写真/地図→基本情報→周辺、という順序で、雰囲気や信頼補強情報を後ろに回す設計思想を明示している。

6. **一覧は密度の高いカードで「一目で比較」できるようにする。** サウナイキタイの一覧カードは写真サムネ＋温度/設備/人気指標を1枚に凝縮し、itsumo dogもサムネ＋条件アイコン＋口コミ抜粋を並べる。スクロールせずに候補を比較できる情報密度が探索効率を上げる。

7. **情報鮮度・信頼性を能動的に担保する仕組みを持つ（が「確認日の明示」はどの競合も未対応の空白）。** BringFido（電話一次確認＋保証）、itsumo dog（「情報が古い可能性」警告）、おでかけわんこ部（特派員＋スタッフ確認）、Wan!Pass（証明書審査）と各社が信頼性に投資する一方、「いつ時点の情報か」をユーザーに明示するUIはどのサービスにも見当たらず、明確な市場の空白になっている。

8. **「入れるか」と「どう振る舞うべきか（マナー・条件）」を分離提示する。** itsumo dogは犬同伴条件バッジ（入れるか）と利用マナー11項目（どう振る舞うべきか）を別ブロックにし、犬連れ利用者の実務的不安に応えている。

9. **ユーザー投稿写真（UGC・実体験）を信頼と魅力の核に据える。** おでかけわんこ部・Wan!Pass（みんなの投稿）・BringFido（犬の写真）・Googleマップ（最新訪問者写真）はいずれもUGC写真を「宣伝でない実態」の証拠として前面化し、食べログは写真をカテゴリ分けして到達性を高めている。

10. **保存/お気に入りを地図と統合し、テーマ別に整理できるようにする。** Googleマップ（Youタブのリスト・共有）、Retty（オリジナルリスト）、食べログ（コレクション）が定番機能として持ち、BringFidoでは「お気に入りを地図上で見たい」という実ユーザー要望が出ている。単独リスト画面だけでなく地図ピンとの統合表示が求められる。

## 4. Puppy With Cafe の現状ポジション評価

現状UIは、地図画面のスクリーンショット（`docs/screenshots/map_tennoz.png`）と、`RootView.swift` / `MapView.swift` / `CafeListView.swift` / `CafeDetailView.swift` の実装から把握した（詳細画面の追加スクリーンショットは今回参照不可のため、詳細評価はソースコードのセクション構成に基づく）。

### 強み

- **確認日・出典・由来(provenance)の明示は全競合が持たない最大の差別化点。** 詳細ヘッダーに「最終確認日＋出典」を併記し、`未確認`は灰・`1年以上経過`は橙で警告し、AI推測は紫の`sparkles`チップで確定情報と視覚区別している（`CafeDetailView.headerSection` / `ProvenanceChip`）。ベスト・プラクティス7が示す「確認日は業界の空白」を唯一埋めており、憲章 原則I（信頼できるデータ）を体現している。
- **地図起点（現在地から今探す）をコアに据えている。** itsumo dog（地図は詳細内1タブ）やRetty（一覧起点）に対し、地図が主画面という構造そのものが差別化になる。MKMapViewでクラスタリングも実装済み（`CafeMapView`）。
- **カフェ特化スコープが「カテゴリ横断ゆえのフィルタ簡素化」問題を構造的に回避している。** Wan!Pass・BringFidoがドッグラン/ショップ横断ゆえフィルタが粗くなる不満を抱えるのに対し、カフェに絞ることで店内席/テラス等の深掘りが可能。
- **一覧行の情報密度が良好。** サムネ＋店名＋条件＋営業状態バッジ＋可否バッジ＋距離を1行に凝縮（`CafeRowView`）しており、ベスト・プラクティス6と整合。
- **鮮度・オフライン・サンプルの状態表示が丁寧。** データ更新日バナー、オフライン時刻、未確認/古い情報の警告があり、ホットペッパー（表示と実態の乖離）やGoogle（確認日なし）が抱える弱点を先回りしている。
- **サーバーレス・位置情報を送らない設計はプライバシー優位。**

### 弱み

- **主要CTA（経路案内・報告）が長い詳細リストの最下部にある。** `CafeDetailView` の `actionSection` は写真・設備・営業時間・出典・店舗情報・リンクの全セクションを過ぎた末尾（実装上の最終Section）に置かれ、経路案内に到達するまで大量スクロールが必要。ベスト・プラクティス2・3（探す→行動の最短化／CTA下部固定）から最も乖離している。
- **フィルタが可否ステータスのみ。** `RootView.filterMenu` は `DogPolicyStatus.allCases` だけを列挙する。詳細画面には「店内OK/テラスOK/大型犬OK/犬メニュー」（`dogAmenities`）のデータが既に存在するのに、絞り込み軸として使われておらず、ベスト・プラクティス4（条件フィルタ）と市場標準（おでかけわんこ部/Wan!Pass/itsumo dog）に未対応。
- **地図に凡例がなく、可否・営業中が地図上で伝わりにくい。** マーカーは全店 `🐶` グリフで色分けのみ（`markerTintColor`）。凡例（緑=可/橙=条件付き/赤=不可/灰=未確認）がないため色の意味が伝わらず、ホットペッパーの「即時性の地図可視化」やドッグパークJPの2色凡例に劣る。
- **地図ピンの簡易カード（Compact段）が薄い。** callout は標準の吹き出し＋detailDisclosureで実質「店名のみ」。可否/距離/営業中を含む簡易カードにできていない（GoogleのCompact、Retty/食べログのピン→簡易カードに対し1段目が弱い）。
- **保存/お気に入り機能が存在しない。** 全競合が持つ基本機能で、地図統合の要望も強い（BringFido）。
- **最大の差別化点である確認日が footnote サイズで視覚的に埋もれている。** `headerSection` の確認日は `.font(.footnote)` の控えめな表示で、競合が持たない強みを前面化できていない。
