safeAreaInset(edge: .bottom) で固定

内容（UI変更）
CafeDetailView の List に .safeAreaInset(edge: .bottom) で固定アクションバーを追加し、「経路案内（マップで開く）」と「電話」（cafe.phone がある店のみ）を常時表示する。既存 viewModel.openInMaps() と tel:// リンクを再利用。電話が無い店では経路案内を全幅ボタンにする。
根拠
食べログ「地図ページに予約ボタンを追加し探す→行動を最短化」、グルメアプリ共通の「フッター固定CTA」、Retty「電話重視CTA」、GoogleマップのCompactカードから即経路。
期待効果
経路案内という本アプリのコア動機に直結する行動を1タップ圏に引き上げる。
憲章整合
経路はMapKitで端末内完結・位置送信なし、電話はtelスキームで整合。新規依存なし。

内容（UI変更）
RootView.filterMenu に設備トグルのSection（店内OK・テラスOK・大型犬OK・犬メニュー）を追加。CafeListViewModel に amenityFilter を新設し絞り込みに組み込む。dogAmenities が nil の店は「不明」として、設備条件選択時は結果から除外する（憶測で満たさない）。フィルタ適用中はツールバーのアイコンにバッジ（適用件数）を表示。
根拠
おでかけわんこ部「店内OK/大型犬可/テラス席あり」、itsumo dog「中型/大型犬OK/店内OK」、Wan!Pass「犬種・体格連動フィルタ」、サウナイキタイ「細分化フィルタ」。
期待効果
既存データ（dogAmenities）を検索資産に転換し、市場標準に追いつく。
憲章整合
既存データ項目の範囲内で推測補完をしない（nil=不明を満たさない扱い）ため原則Iを損なわない。データ送信なし。

内容（UI変更）
CafeDetailView.headerSection の「最終確認日＋出典」を、可否バッジ近傍の視認性の高い「確認済みチップ」に昇格（例: checkmark.seal.fill＋確認日をprimaryサイズのCapsuleで）。未確認・1年以上経過の警告は色・アイコンを維持。一覧行（CafeRowView）にも古い/未確認時のみ小アイコンを添える。
根拠
全競合（食べログ/Google/ホットペッパー/BringFido）が「確認日」を明示しない市場の空白。この空白こそ本アプリ唯一の構造的優位。
期待効果
「いつ確認したかが分かる」差別化をUIで前面化し、信頼とリテンションに寄与。
憲章整合
原則I（由来提示）を直接強化。既存フィールド（lastVerified/representativeSource）の見せ方変更のみ。

内容（UI変更）
(a) CafeMapView のマーカーcalloutにsubtitleを付与し「可否＋距離＋営業中/営業時間外」を表示。(b) RootView の地図に小さな凡例オーバーレイ（緑=可/橙=条件付き/赤=不可/灰=未確認）を重畳し、markerTintColor の意味を明示。凡例は .regularMaterial 背景の小カードで邪魔にならない大きさに。
根拠
GoogleマップのCompact/Full2段階開示、Retty/食べログの「ピン→簡易カード→詳細」、ホットペッパー「即時性を地図で視覚化」、ドッグパークJPの2色凡例。
期待効果
詳細を開かずとも「入れる・近い・今営業中」が地図上で判断でき、地図起点アプリの強みを最大化。
憲章整合
表示のみ。位置送信なし・データ契約変更なし。

未決点（オーケストレーター判断を仰ぐ点）

  • P0の実装順: 4件とも独立着手可能。推奨は P0-3 → P0-1 → P0-4 → P0-2。P0を3件に絞るなら P0-4 をP1へ降格しても可。
  • P0-2の nil（設備不明）店の既定挙動 → 実データで解消済み（2026-08-05 実測）: dog_amenities 保有 263/268件。判明数は 店内OK 227・テラスOK 193・犬メニュー 55・大型犬OK 0件。店内OK/テラスOKは「不明店を除外」方式で成立。犬メニューは補助扱い。大型犬OKはデータ0のためフィルタ化不可（先にデータ収集が必要）。
  • 調査上の注記: 詳細画面のスクリーンショットは指定パスに存在せず参照できなかった。詳細・一覧の提案は実装コードのセクション構成に基づく（地図画面のみ実機スクショで確認済み）。写真セクションのフォールバック挙動に関する追加のUI改善余地は、実機スクショ入手後に再評価するのが望ましい。
