既存の店の空欄を埋める作業は `gap-handover-2026-08.md`。こちらは**まだ掲載していない犬同伴OKの店を新しく載せる**作業の基準。2026-10-30〜11-01 のバッチR〜AA（新規240店）で、QA の差し戻しから固まった基準をまとめた。まず `README.md`（絶対ルール）と `tools/README.md`（列の仕様）を読むこと。

## 流れ（cc-crew）
1. 調査（cafe-researcher・1体12店まで・1エリア6店まで）: 担当エリアで候補を探し、`result-N.json` で納品（`shops` に `status: ok|candidate_weak`、`excluded` に見送りと理由）。既存店（＋同時に進む他バッチの掲載予定）と照合して重複を除く。
2. メインが DECISIONS（個別判断）を書く。
3. 反映（builder・1体）: id を main の最大の次から採番し、3つの CSV の末尾に**バイト単位で追記**（cafes・coord_sources は CRLF、sources は LF。既存行は変えない）。`export_cafes.py` を1回だけ実行。
4. QA（qa-reviewer・別体）: 食べログ・公式の原文を取り直して全店を突き合わせる。FAIL なら直して再 QA。
5. PR → マージ（＝配信）。

## 掲載してよい店
- **犬の根拠が店舗側の記載**であること。認めるのは次のどれか:
  - 公式サイト・公式SNS（プロフィール・お知らせ）、公式ニュースリリース
  - 食べログで「**店舗関係者によって公開**」かつ「**ユーザーの皆様は編集することができません**」の表示がある店の、備考・PR・こだわり・席数などの欄
  - 食べログがユーザー編集可能（「最近の編集者」「編集履歴」あり）でも、犬の記載が **PR 文・こだわり欄など店舗側の欄**にある店
  - ぐるなび等の店舗ページで同じ内容が確認できる店
- **認めない**: ユーザー編集可能な食べログで、犬の記載が**備考欄・サービス欄（「ペット可」の属性）・「お子様連れ」欄だけ**の店（バッチT で4店、V で1店、X で2店がこれで QA 差し戻し）。紹介サイト・ブログ・口コミだけの店は `candidate_weak`。
- 「犬」と書かず「ペット」とだけ書く店は可（犬はペットに含まれる）。PR 文の「お散歩途中にお立ち寄りください」のような、同伴できるとまで書いていない文は根拠にならない。
- **今も営業している根拠**（1年以内の口コミ、公式の最新のお知らせ等。日付つき）があること。口コミが開店時の1件だけ・2年近く前だけの店は載せない（KUDZU SWEETS LALA・カフェ ユエ）。閉店予告・掲載保留・開業前の店も載せない。
- **常設の飲食店**であること。日を決めたポップアップ・イベント時だけ・BBQ 貸切・物販中心の店は載せない（ピーナッツクラブ カフェ・EDIT(h)）。夜だけの居酒屋・バーは優先度を下げる（禁止ではない）。

## 列の決め方
- **dog_indoor**: 原文に「店内」の語（「店内OK」「入店可能」「店内全席」等）があれば true。「テラス席のみ」「テラス席に限り」「外のお席のみ」があれば false。どちらもなければ**空**。「全席ペット可」だけ、座椅子・足元・カートの記載だけ、屋外席の記載がないことから店内と推測しない（cafe MJ・梶田珈琲・JUNOS・Toritoco）。
- **dog_terrace**: 「テラス席はペット可」「テラス席で〜」なら true（店内は空のまま。前例 LOOK UP COFFEE）。
- **claimed_status**（ルール a）: 席・場所・予約・時間帯の制限（「テラス席のみ」「一部の席」「月曜14時以降は店内可」「予約時に要望欄へ」）があるときだけ conditional。大きさ・頭数・料金・マナー（「小型犬のみ」「2組まで」「1頭500円」「おむつ着用」）だけなら allowed で条件文は空（事実は dog_note へ）。
- **claimed_condition**: 原文の**一文**。2つの欄をつなげない。要約しない。原文にない「のみ」を足さない。
- **大きさ**: 「大型犬もOK」「大型犬はテラスのみ」→ dog_large=true（後者はテラス large）。「大型犬を除く」→ dog_large=false、上限 medium。「小型犬可」だけなら空。3列は該当する側の dog_indoor/dog_terrace が true の店だけ（export が検証）。
- **dog_menu**: 店側の欄に犬用メニュー・犬用おやつの販売が明記されていれば true。
- **電話**: 公式に記載があるか、独立した2サイト（日本語版で「電話」と表示。FAX と取り違えない）で一致。050 の転送番号・予約代行の番号は入れない。アンバサダー等の個人サイトは独立した出典にならない。
- **営業時間**: 
  - 公式と食べログで食い違えば hours_text・holiday_note・曜日列を空。
  - 「時間変更有」「中休みあり」「当日お問合せ」「11時開店になる日あり」「イベントで変わる」等があれば曜日列は空（hours_text に注記を残す）。「不定休」だけ・「臨時休業は SNS で告知」だけなら曜日列を入れてよい。
  - 曜日の指定も定休日もない時刻だけなら曜日列は空。「定休日 なし」の明記があれば holiday_note は「定休日なし」で全曜日を入れてよい。
  - 連続した帯（10:00-17:00 と 17:00-23:00）は曜日列では1つにまとめる。hours_text は原文どおりの帯。L.O. と最終受付を取り違えない。
  - 反映の直前に食べログを取り直し、更新があれば最新に合わせる。
- **description**: 営業形態の事実と合わせる（夜営業があるのに「ランチ営業の店」と書かない）。「20歳未満は入店不可」「未就学児不可」「全席喫煙可」など犬連れの利用に関わる店側の事実は書く。口コミが出どころの表現（「住宅を改装した」）は書かない。
- **調査メモ・出典名の注記を値に書かない**（「（公式サイトの定休日欄）」「（食べログの案内）」等。ルール c）。予約の情報は reservation 列へ。
- **sub_area**: 既存の表記から、同じ町の既存店に合わせる。駅からの距離で明らかに別の街なら新設してよい（新設例: 目白・千駄ヶ谷・代々木・両国）。
- **Instagram**: 公式サイトのリンク先と食べログの表記が食い違えば空。

## 座標（台帳 coord_sources.csv に各店1行）
- 食べログ JSON-LD の geo（小数6桁）。国土地理院の逆ジオコーダで**町丁目が住所と一致**すれば method=shop_pin_single（distance_m 空、note「新規掲載（旧座標なし）。単一出典・GSI町名: …」）。
- 一致しなければ、食べログ以外の店舗ピン（公式の店舗ページの JSON-LD・地図埋め込み等、ページに書かれた数値）を探し、100m 以内で一致すれば method=shop_pin（distance_m 空、note「2点目: <種別> <URL> <距離>m」）。住所から割り出した座標（2店で同じ値など）は店舗ピンとみなさない。見つからなければ載せない（ル パティシエ タカギ・ニュウマン高輪の2店）。
