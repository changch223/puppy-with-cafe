### Session 2026-08-08（Google Maps流ナビ・出典の記事カード化）

- Q: 「出典」セクションをどう見せるか → A: UI表示名を「出典」から**「参考記事」**へ改称し、各出典（記事）を**記事カード**として提示する。カードには OGP代表画像（記事URLから端末側で取得）・記事タイトル（OGPタイトル、なければ出典種別名）・運営要約（claimed可否・確認日・採用根拠バッジ）を1枚にまとめ、クリックせずに写真と要点が分かるようにする。カードタップで元記事を開く（既存のリンク開示ルール: http(s)はアプリ内ブラウザ、instagram/xは外部アプリ）。データの契約（`Source` の種別・URL・可否・確認日・由来）自体は変更しない（UI表示層のみの改称・再構成）。
- Q: 記事カードの代表画像はどう取得するか → A: 既存の「写真・雰囲気」機能と同じ **`LinkPreviewService`（端末側のリンクプレビュー、`LPMetadataProvider`）** を再利用する。画像はサーバー側での収集・保存・再ホストは一切行わず、常に利用者の端末が記事URLへ直接アクセスして取得する（画像のスクレイピング・転載・再ホストの禁止、憲章・research-agentルール#6と整合）。取得に失敗した場合、またはOGP画像を提供しない出典は、アイコン＋タイトルのテキストカードにフォールバックする（既存の写真カードのフォールバックと同じ挙動）。
- Q: 参考記事が多いカフェでの取得コストは → A: OGP画像の取得は先頭5件までに限定し、それ以降はテキストカードのまま追加のネットワーク取得を行わない（`LinkPreviewService` 既存の3並列制限・キャッシュ・negativeキャッシュとあわせてスロットルする）。

### Session 2026-08-08（詳細画面の再構成・営業時間統合・日跨ぎ対応）

- Q: セクション順・営業時間の見せ方をさらに見直すか → A: 営業時間（バッジ＋当日の時間）を独立セクションから**ヘッダーへ統合**する（独立の「営業時間」セクションは廃止）。運営確認日チップ（P0-3で追加したCapsuleチップ）は**表示を一旦抑止**する（ロジック・データは保持し、未確認・鮮度の警告表示（FR-009/FR-010）で注意喚起は引き続き行う。後で表示を戻せるようにする）。ヘッダーの条件付き1行要約（「来店に条件があります（詳細は下記…）」）は視認性を抑えた小さめの文字（caption）にする。セクション順を ヘッダー（営業時間統合）→わんちゃん向け情報→写真・雰囲気→参考記事→公式情報・SNS→来店時の条件・マナー→出典間の食い違い（矛盾がある場合のみ）→店舗情報→アクション に変更する。
- Q: 深夜営業・日跨ぎ営業（例: 22:00-2:00）を構造化できるようにするか → A: 対応する。閉店時刻は**24:00（当日終端＝翌0:00）まで**を許容し、**開店時刻 ≧ 閉店時刻の場合は日跨ぎ営業として扱う**（例: 18:00-2:00）。営業中判定（`OpeningHoursEvaluator`）は日跨ぎ区間（open〜24:00 と 0:00〜close の和集合）で正しく判定する。従来「日跨ぎ営業は登録エラー・フリーテキストで表現」としていた制約を撤廃する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 詳細画面だけで「行くかどうか」を決められる (Priority: P1) 🎯

利用者はカフェ詳細を開くと、犬同伴可否に加えて、営業時間（と今営業中か）、犬向け設備（店内OK・テラス・大型犬・犬用メニュー）、電話・予約情報、公式サイトや Instagram へのリンク、運営が公式SNSで確認したメモ（確認日つき）が見える。アプリの外に出ずに「今から行けるか・うちの子と入れるか・どう予約するか」をおおむね判断でき、最終確認したい人はリンク先の公式情報に飛べる。

**Why this priority**: 本フィーチャーの核心。「アプリを見ればどこに行くか決められる」を実現する。

**Independent Test**: 情報が登録されたカフェの詳細を開き、営業時間＋営業中バッジ・犬設備4バッジ・電話（タップで発信）・予約情報・公式リンク集・転記メモ（確認日つき）が表示されること。未登録の項目はセクションごと非表示になり「不明」を「なし」と誤認させないこと。

**Acceptance Scenarios**:

1. **Given** 営業時間（構造化）が登録されたカフェ, **When** 現在時刻が営業時間内に詳細/一覧を見る, **Then** 「営業中」バッジが表示される（時間外なら「営業時間外」、定休曜日なら「本日定休」）。
2. **Given** 営業時間がフリーテキストのみのカフェ, **When** 詳細を見る, **Then** テキストが確認日つきで表示され、バッジは表示されない。
3. **Given** 犬向け設備が登録されたカフェ, **When** 詳細を見る, **Then** 店内OK/テラスOK/大型犬OK/犬用メニューが ✓/✕ で示され、未入力の項目は「不明」として区別される。
4. **Given** 公式リンク（HP/Instagram/X等）が登録されている, **When** リンクをタップする, **Then** 外部ブラウザ/アプリで開く。
5. **Given** 運営転記メモ（例:「公式Instagramより: テラス席は雨天クローズ」）がある, **When** 詳細を見る, **Then** メモが**出どころと確認日つき**で表示され、確定情報と誤認させない。
6. **Given** 電話番号が登録されている, **When** タップする, **Then** 電話発信の確認が出る。

### Edge Cases

- **情報未登録**: 未登録の項目・セクションは非表示（空欄・「なし」と誤認させない）。犬設備の未入力は「不明」表示。
- **営業時間の鮮度**: 営業時間・基本情報には確認日を併記し、古い場合（1年超）は既存の鮮度警告の対象に含める。
- **深夜営業・複数時間帯**: 同一曜日に複数の時間帯（例: 9:00-12:00, 13:00-18:00）を扱える。日跨ぎ営業（開店≧閉店。例: 22:00-2:00）・24:00終端（例: 17:00-24:00）も構造化して登録でき、営業中判定は日跨ぎ区間を正しく判定する（2026-08-08改訂。従来は登録エラーとしフリーテキストで表現させていた）。
- **タイムゾーン**: 営業中判定は日本時間（Asia/Tokyo）固定（v1は東京のみ, 001/FR-022）。
- **参考記事のOGP代表画像が取得できない**: 記事側がOGP画像を提供しない、通信に失敗した、取得上限（先頭5件）を超えた、のいずれの場合もアイコン＋タイトルのテキストカードにフォールバックし、記事カード自体は表示され続ける（機能不全にしない）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-101**: カフェは任意で 電話番号・予約情報（テキスト）・営業時間（フリーテキスト）・営業時間（曜日別の構造化）・公式リンク集（website/instagram/x/tabelog/googlemap/other）・犬向け設備（店内OK/テラスOK/大型犬OK/犬用メニュー、各 ✓/✕/不明）・犬設備の自由記述・運営転記メモ（本文＋出どころ＋確認日）・基本情報の確認日 を保持できなければならない (MUST)。
- **FR-102**: 構造化営業時間を持つカフェには、現在時刻（Asia/Tokyo）に基づく「営業中／営業時間外／本日定休」バッジを一覧・詳細（詳細ではヘッダーに統合、FR-111）に表示しなければならない (MUST)。開店時刻が閉店時刻以上の場合は日跨ぎ営業（例: 22:00-2:00）として、閉店時刻は24:00（当日終端）まで許容して判定しなければならない (MUST)（2026-08-08改訂）。構造化を持たないカフェにはバッジを表示してはならない (MUST NOT)（推測で「営業中」と示さない）。
- **FR-103**: 運営転記メモは出どころ（例: Instagram）と確認日を必須とし (MUST)、公式の一次情報そのものではないことが分かる形で表示する。確認日のないメモは配信してはならない (MUST NOT)。
- **FR-104**: 未登録の情報は非表示または「不明」として提示し、「なし/✕」と誤認させてはならない (MUST NOT)。
- **FR-105**: 追加情報はすべて既存のデータ契約（cafes.json format_version 1）への**後方互換の追加**として配信し、検証（時刻形式・URL形式・enum・確認日必須）を通過しないデータは配信してはならない (MUST NOT)。
- **FR-106**: 電話番号はタップで発信でき、公式リンクは外部で開けなければならない (MUST)。
- **FR-107**: カフェは任意で 地区名（sub_area, 例: 天王洲アイル）・店舗紹介（description）・犬のサイズ制限メモ（dog_size_limit）・定休日メモ（holiday_note）を保持し、詳細画面に表示できなければならない (MUST)。入力値 `unknown`/`不明` は「不明」として扱い、「なし/✕」と混同してはならない (MUST NOT)。Instagram のリンクは @ハンドル入力を URL に正規化して受け付ける。

#### 詳細画面のUX（UI/UXブラッシュアップ, P0/P1/P2-4）

- **FR-108**: カフェ詳細画面は「経路案内」ボタン（電話番号がある場合は「電話」ボタンも併記）を、スクロールに追従しない固定バーとして画面下部に常時表示しなければならない (MUST)。
- **FR-109**: 最終確認日は、可否バッジの近傍に視認性の高いチップ（アイコン＋「運営確認 YYYY-MM-DD」）として実装・保持しなければならない (MUST) が、v1では表示を抑止する（2026-08-08改訂。ロジック・データは維持し、必要になれば表示を戻せる状態にする）。未確認、または確認日が既定のしきい値（365日、FR-010）を超えている場合は、既存の警告表示（未確認バナー・鮮度警告）でその旨を示さなければならない (MUST)。
- **FR-110**: 来店時の条件（`dogPolicyCondition`）・犬のサイズ制限メモ（`dogSizeLimit`）・自由記述の犬向け注記（`dogNote`）は、「来店時の条件・マナー」セクションに集約して提示しなければならない (MUST)。ヘッダーには条件付きである旨の1行要約のみを、視認性を抑えた小さめの文字（caption、2026-08-08改訂）で残す。
- **FR-111**: カフェ詳細画面のセクションは、ヘッダー（営業時間バッジ・当日の時間を統合、FR-102）→わんちゃん向け情報（設備）→写真・雰囲気→参考記事（旧称: 出典）→公式情報・SNS→来店時の条件・マナー→出典間の食い違い（矛盾がある場合のみ, 001/FR-011）→店舗情報→アクションの順で表示しなければならない (MUST)（各セクションは該当情報がある場合のみ表示する。FR-104。2026-08-08改訂: 独立の営業時間セクションを廃止しヘッダーへ統合、順序を変更）。
- **FR-112**: 利用者はサインインなしで、カフェを端末ローカルのお気に入りとして登録・解除できなければならない (MUST)。お気に入りは端末のUserDefaultsに保存し、位置情報を伴わず、外部への送信・同期を行ってはならない (MUST NOT)。お気に入り状態は詳細画面のトグル・一覧行・地図ピンで一貫して視覚的に確認できなければならない (MUST)。

#### 参考記事の記事カード化（UI/UXブラッシュアップ, Google Maps流ナビ）

- **FR-113**: カフェ詳細の「参考記事」セクションは、各出典（001/Key Entities の `Source`）を記事カードとして提示しなければならない (MUST)。記事カードには、記事URLから端末側で取得したOGP代表画像（取得できる場合）・記事タイトル（OGPタイトル、なければ出典種別名）・運営要約（claimed可否バッジ・確認日・矛盾解決の採用根拠バッジ）を含めなければならない (MUST)。これにより FR-008（出典・確認日の提示）を満たす。
- **FR-114**: 記事カードの代表画像は、既存の「写真・雰囲気」機能と同じ端末側リンクプレビュー機構（`LinkPreviewService`）でのみ取得しなければならない (MUST)。画像をサーバー側で収集・保存・再ホストしてはならない (MUST NOT)（画像のスクレイピング・転載・再ホストの禁止、憲章および research-agent ルール#6と整合）。OGP画像の取得に失敗した場合、または出典がOGP画像を提供しない場合は、アイコンと記事タイトルのみのテキストカードにフォールバックしなければならない (MUST)。
- **FR-115**: OGP代表画像の取得は、パフォーマンス上の上限として1カフェあたり先頭5件までに限定してよい (MAY)。上限を超える出典はテキストカードのまま表示し、追加のネットワーク取得を行わない (SHOULD NOT)。

### Key Entities（001 からの追加分）

- **公式リンク (CafeLink)**: 種別（website/instagram/x/tabelog/googlemap/other）とURL。
- **営業時間 (OpeningHours)**: 曜日→時間帯配列（open/close, "HH:mm"）。定休曜日は空配列。close は `24:00`（当日終端＝翌0:00）まで許容し、open ≧ close（例: 22:00-2:00）は日跨ぎ営業として扱う（2026-08-08改訂）。
- **犬向け設備 (DogAmenities)**: indoor/terrace/large_dogs/dog_menu（各 true/false/不明=null）。
- **運営転記メモ (OperatorNote)**: 本文・出どころ（instagram等）・確認日（必須）。
- **お気に入り (Favorite)**: 利用者が端末に保存する「気になる/行きたい」カフェの印。属性はカフェID。サインイン・同期・位置情報を伴わない端末ローカルの状態（UI/UXブラッシュアップ、FR-112）。

## Success Criteria *(mandatory)*

- **SC-101**: 情報が登録されたカフェについて、利用者は詳細画面から離脱せずに「営業中か・犬設備・予約方法・公式リンク」を確認できる（外部遷移は任意）。
- **SC-102**: 「営業中」バッジの判定が構造化データに対して100%正確（判定ロジックはユニットテストで担保）。
- **SC-103**: 未登録項目が「なし/✕」と表示されるケースが0件（不明は不明と表示）。
- **SC-104**: 確認日のない転記メモ・不正な時刻/URLを含むデータの配信が0件（エクスポート検証で拒否）。
- **SC-105**: お気に入りに登録したカフェは、アプリを再起動しても登録状態が保持される（端末ローカル永続化、FR-112）。
- **SC-106**: 参考記事の記事カードに表示される画像は、常に利用者の端末が記事URLへ直接アクセスして取得したOGP画像であり、サーバー側で収集・保存・再ホストされた画像である割合が0件である（画像の転載・再ホスト禁止、FR-114、憲章・research-agentルール#6）。

## Assumptions
